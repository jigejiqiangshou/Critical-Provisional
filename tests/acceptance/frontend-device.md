原型来源为原工作区的 Git 提交 `6eb37d4159c8e70d4d4a43a7926861ca8becdda7`。从旧会话的文件写入记录和独立测试的 `git show` 输出恢复的版本见 `a494c29babbca37a6b3601dcfe5d1dcfad88488b`。恢复后两份安装包的字节数、gzip 大小及 SHA-256 与原独立复验一致。

## 样本体积

用 Node.js 24 运行 `node scripts/build-frontend-spike.ts`，从只读的 `quote/临界·模块化·3D版.html` 提取原嵌入的 Three.js r128 和全部 JPEG 数据 URL。60 个引用含 58 个不同的数据 URL。官方样本把这些数据和 3D 探针写入自包含 `entryHtml`。探针使用原版 560 × 840 牌面绘制小场景。其余牌面保留在下载、解析和缓存的字节测量中。正式 3D 视图及其完整解码和显存占用由后续任务验收。

| 样本 | UTF-8 字节 | gzip 字节 |
|---|---:|---:|
| 旧版 3D 整页 | 11,294,266 | 8,031,033 |
| 官方 3D 资源样本 `official-3d.critical-ui` | 10,932,804 | 7,911,369 |
| 本机导入样本 `third-party.critical-ui` | 5,012 | 2,176 |

Three.js 为 603,445 字节，JPEG 数据 URL 共 10,313,408 字节。生成的 `.tools/frontend-spike/sample.json` 记录各样本的 SHA-256 及可复查的字节数。官方样本的 SHA-256 为 `5d4195059d0b64e4f6a096590143a4ff483c1266756d5d367e1d3484841121fa`，第三方样本为 `a65e1b84cb4376c2185166cfdf6551df1984b7b308fe3152887636eb7d2c3666`。

开发暂定包体上限为 **10,932,804 字节**，取已在桌面成功缓存、离线冷启动并实际出帧的官方 3D 样本大小。按收到的 `.critical-ui` 文件字节数计。T049 用相同样本复验桌面与 Android 的包体边界，确定首版上限。

## 复验入口

```sh
npm ci
node scripts/build-frontend-spike.ts
python -m http.server 43104 --bind 127.0.0.1 --directory .tools/frontend-spike
```

从另一个终端核对官方样本为 `10932804` 字节，静态源站的包入口返回 `404`。

```sh
wc -c < .tools/frontend-spike/official-3d.critical-ui
curl --silent --output /dev/null --write-out '%{http_code}\n' http://127.0.0.1:43104/__t004__/entry
```

桌面本机访问 `http://127.0.0.1:43104/`。手机须通过可访问的专用 HTTPS 静态部署安装。将 `.tools/frontend-spike/` 作为完整站点目录提供，保持 PWA 的 scope 与启动地址相同。静态源站的 `__t004__/entry` 应返回 404。该 URL 的包内容和 CSP 由本实验的 Service Worker 提供。请选择原型专用 origin，以隔离站点缓存和已有应用存储。

1. 从空存储安装宿主。从安装图标打开，看到“宿主离线资源已准备”。把第三方样本下载到手机或电脑本地文件系统。选择器允许选择任意扩展名，包头、样本 ID 与协议版本在读取后校验。
2. 点击“准备并打开官方 3D 样本”。从验证记录保存包体积、读取耗时、缓存耗时、存储估算、WebGL 版本、渲染设备、两帧的像素与耗时。验证宿主为已安装窗口且受 Service Worker 控制。
3. 点击“验证专用端口”检查同一实例的回复。在 iframe 内点击“验证导航撤销”。宿主应撤销端口、清除 iframe 并禁用验证按钮。
4. 完全退出宿主，断网，从安装图标重新打开。点击“打开已保存的 3D 样本”。核对两帧绘制、缓存入口和专用端口。读回的记录应包含 `online: false`。
5. 保持断网，用系统文件选择器选取一份将 `protocolMajor` 改为 `99` 的第三方样本，预期报告协议不兼容且无已保存条目。再选取本地原始的 `third-party.critical-ui`，检查握手、专用端口及隔离。关闭应用以后继续断网启动，由“打开已保存的第三方样本”再启动，核对新握手标记。
6. 保留每次设备、系统、浏览器、安装入口、断网方法、文件选择、隔离及渲染结果。记录配额或内存异常以及失败阶段。

## 桌面云环境证据

| 平台 | 已取得的证据 | 待核验 |
|---|---|---|
| Linux 桌面 Chromium | Debian 13 x86_64，Chromium 156.0.8078.79，Node.js 24.22.3。DevTools `PWA.install` 安装，独立显示模式，`PWA.launch` 启动。使用相同 profile 完全重启 Chromium 进程并离线启动，静态服务器已关闭。3D 仍能打开并出帧。通过浏览器文件选择事件选取本地文件，断网导入成功，再次重启仍能打开。 | 其它桌面系统和硬件渲染表现 |
| Android Chrome 安装 | 由 T049 用正式候选构建复验 | 安装、文件选择、断网冷启动、WebGL、存储隔离和首版包体上限 |

桌面样本读取和解析约 247 ms，到缓存完成约 445 ms。ANGLE/SwiftShader 软件渲染的 WebGL 2.0 在线、离线均读取两帧不同中心像素 `[221,216,210,255]` 和 `[217,213,205,255]`，每帧中心和背景像素不同。在线渲染约 389 ms，冷启动后渲染约 581 ms。该耗时是一次运行的环境观测值。准备官方样本后的 CacheStorage 占用约 10.96 MB。端口 ping 得到回复，主动导航后宿主关闭端口。官方和第三方样本均发送 `origin: "null"`，访问宿主 DOM、localStorage、IndexedDB 与 CacheStorage 得到 `SecurityError`，网络请求触发 `connect-src` 拒绝。

原版独立复验于 Chromium `156.0.8078.79` 重新构建并核对全部 JPEG 引用与 Three.js，确认两次离线冷启动、错误协议拒绝、本地文件选择与导入、实际像素读回、宿主隔离及导航和手动关闭后的端口撤销。验证前终止静态服务，冷启动间完整结束 Chromium 进程并以同一安装配置启动。在可用桌面复验时，保留安装模式、浏览器完整版本、包体字节、隔离结果及两帧像素。

开发自查观察到 Chromium 对初始 `sandbox="allow-scripts"` iframe 导航跳过宿主 Service Worker，直接到静态源站的 404。原型初始 iframe 属性额外允许同源路由，受控响应使用自己的 `Content-Security-Policy: sandbox allow-scripts`，所以样本文档运行前已取得不透明来源。宿主限制 iframe 可加载的路径，核验匹配的 Service Worker、实际 frame、一次性实例标记和 `null` 消息来源，在首载时移除属性中的额外权限，随后才传递端口。缺失受控入口或握手时没有端口，后续加载和关闭实例会撤销端口。该路由方式需要在目标移动浏览器上复验，结果作为 T005、T019 的输入。

原型使用专用缓存和探针协议，仅验证样本下载、准备、存储、隔离及入口生命周期。活动安装记录、失败回退和正式玩家授权由对应后续任务验收。
