# 离线验收指南

以下命令由实施任务定义。执行前准备 Node.js 24 LTS、iOS 与 Android 实机、桌面 Chromium，以及供所有设备访问的 HTTPS 构建预览。开发命令为 `npm ci`、`npm run dev`。验证命令为 `npm run test`、`npm run test:baseline`、`npm run test:e2e`。用 `npm run build` 生成站点与前端包，并将静态产物放到 HTTPS 预览。WebKit 模拟验证可用于早期检查，最终以已安装的实机实例为准。

## 安装、冷启动与权限

1. 在三类设备安装主体。iOS 从主屏幕图标打开，再在该实例内安装官方 2D、3D。等待启动器报告主体及前端就绪。准备兼容的第三方示例包和不兼容样本到本地文件。
2. 关闭所有窗口，手机开启飞行模式、电脑禁网，且关闭另一台设备。由安装图标重新打开游戏。官方 2D 通过触控或鼠标完成一局操作，官方 3D 验证选牌、目标、镜头、决策与 WebGL。
3. 在离线状态导入第三方示例包。关掉应用再次离线打开，从列表进入对局。分别验证导入资源缺失、损坏、不兼容、ID 冲突、空间不足及写入配额失败时的反馈。断网时从新装入口导入已安装前端的同 ID 新版本，核对 ID 冲突。再从该前端的升级入口选择同一文件，先取消来源确认并核对旧版仍为活动版，再确认来源并继续。验证候选版加载已验证入口、完成端口握手及协议协商之后才成为下次打开时使用的活动版。让旧版停在一个待决策项上并完成升级，核对旧版界面和有效端口仍可使用，并提交原选择继续结算。关闭旧实例，再从启动器打开该前端，核对加载新版并按正常流程重新授权。分别模拟入口加载失败、握手超时及协商失败，核对原因、候选端口清理、旧活动实例和仍有效的授权；候选版的启动检查端口仅用于握手和协商。另在无同 ID 安装记录的实例验证初装入口失败、握手失败、协商失败及活动记录提交失败。核对候选端口已撤销、列表无对应安装项，同 ID 修正后仍可从新装入口导入。卸载示例包，检查已有卡组和回放仍可打开。
4. 分别记录 iOS、Android 和桌面的机型、系统、浏览器、安装入口、断网和另一台设备关机状态、触控或鼠标结果、3D 出帧、镜头与拾取表现及复现步骤。每台设备的安装图标冷启动、离线开局、2D 和 3D 操作、第三方离线导入均达到预期后才计入 SC-010。云端浏览器证据用于 SC-012–SC-014。
5. 使用测试客户端验证观战只见公开信息，第三方席位只见自己的允许视图且没有试算及宿主存储权限。卸载、重载或离开后旧连接无法再使用。核对官方客户端和第三方沿统一协议提交动作。分别升级客户端与核心，验证同版命令、查询、事件效果一致。另用主版本不符和无共同次版本的连接验证独立诊断、连接关闭及无业务访问。

## 首次发行版与空存储验收

1. 从没有游戏数据的安装实例开始，经正常入口完成首次准备。完全关闭应用并断网，从安装图标冷启动。核对可直接读取已校验的首个官方发行版，以其预设牌表开局、在构筑中查询该发行版，并在卡池编辑器中用该版本创建草稿。
2. 在独立空存储实例中模拟首次装载中断。核对目录无部分发行版且应用尚未报告离线就绪。重试后核对目录只有一份完整的首个官方发行版，重启仍可读取同一发行 ID 和规则版本。

## 五个离线业务场景

| 场景 | 操作与预期 |
|---|---|
| PVE 初始化 | 用合法牌表分别从 2D 和 3D 发起，对照旧版真人先手、双方起手和首回合。提交非法牌表或不可用模型，收到失败原因，且无就绪事件。 |
| 待决策的出牌 | 从固定局面用 2D 触发待决策。仅应答席看到候选。合法应答继续结算，各端只显示授权范围内的结果。重复、过期、越权和非法应答均无新增结算。用其他席位和已撤销的连接提交已经处理过的命令 ID，核对授权检查先于回执查询，且不会暴露回执内容或是否存在。 |
| 构筑保存 | 保存合法牌表并重启，核对名称、牌表、发行版。模拟写入失败。用断网手机导入电脑导出的卡组，同版导入保持文件字段，跨版本导入按下述用例验收。 |
| EVE 初始化 | 独立配置两席 V6 实例及其牌表并开始准备。确认双席和公开视图就绪，首个模型动作尚未执行。替换为不可用模型，检查失败席位及无就绪事件。 |
| 卡池发布 | 从发行版建立两个草稿。无效引用和中断各验证版本数及通知不变。有效发布后重启读回新版，进行中的对局仍按旧效果。多窗口模拟争抢，确认只出现一个写入所有者。 |

## 跨版本卡组导入

1. 在源设备导出一份合法卡组。在缺少源发行版的断网目标设备，选择包含相同卡牌 ID 的另一发行版。让其中至少一张牌的卡面或效果不同，且整副牌表仍符合目标构筑规则。导入并重开，核对名称、ID、数量和引用的目标发行版。
2. 用缺少其中一张牌的目标发行版再次导入，核对错误指出缺失 ID 与目标发行版。另用字段不完整的文件和在目标版本不合法的牌表验证对应诊断。每次失败后核对没有部分记录，原文件和已保存卡组完整可读。

## 续局、规则解算和历史复现

1. 用含待决策的样本依次验证命令确认后尚未收到回执时断开、等待选择时完全退出、应答结果持久确认后尚未送出回执时异常退出。重新接入或经 M07 冷启动续局后核对原席位、待决策、原回执及结算只发生一次。恢复后送达旧 AI 决定须被拒绝。另在原待决策点提交无效选项，核对规则拒绝后用新命令完成选择。重启后原样重试旧命令，核对决策失效。用旧 ID 提交不同内容，核对命令 ID 冲突。两次重试均不得结算或发布新事件。
2. 经可信宿主的授权入口，在独立环境逐一载入该场样本的所有确认点。从等待选择的确认点重放原选择和随机输入，核对结算顺序、局面、回执与版本，确认原对局与原日志不变。比对每条用到的记录与实际加载规则、卡池版本哈希。对版本标识相同但哈希不同以及单条日志不符的样本，验证在开始复现前报错。用未获准的调用验证 M09 拒绝复现、M10 拒绝导出，也不会交付完整候选或原随机输入。用获准开发者入口导出诊断记录，确认带版本哈希。
3. 在同版快照、同输入和随机样本下，对比正式核心与 V6 隔离试算所用解算器。用无需解算器的测试替身验证接口。用含不可见手牌及牌库顺序的样本核对 V6 内部任务仅获迁移必需字段，未获准的调用和协议连接均无法获得该数据。记录受影响行为并核对 V6 通过正常入口完成离线对局。
4. 用含选择和条件分支的多步样本验证通用效果步骤。若实施批量效果重构，记录涉及卡牌、触发和结算差异，随后依目标版本校验整份卡池。核对 T045 的迁移清单，确认首个发行版的每个旧效果均有已实现的新版定义与可追溯来源。

## 行为与回放对照

按[旧版对照样本](contracts/legacy-samples.md)固定来源、初始状态、动作和随机输入。以 LG-01–LG-08 对比每个确认点的结算顺序、关键状态及胜负。[LG-06 无效应答](contracts/legacy-samples.md#lg-06-无效应答)按旧版与迁移版各自的断言验收。新版选一条含随机结算的完整回放，在匹配版本下重放到同一终局，用缺版本、哈希不匹配或不完整记录验证诊断。从普通回放入口以有权席位、对手和观战身份分别打开含私有候选及随机结算的同一回放。核对本席可见结果和公开投影，检查返回内容和更新中未交付越权候选、牌身份或原随机输入。「探珠」的续局另验证原 ID、候选与随机流位置。续局和历史复现分别验证版本与记录诊断，历史复现还覆盖未授权和找不到确认点。

## 架构边界复核

结合[层级总图和各层模块图](contracts/layer-boundaries.md)、[业务交互契约](contracts/business-interactions.md)和关键场景的实际调用记录，复核模块归属、状态所有权，以及跨层 Command、Query 和 Event 的方向和业务含义。M05 核对由构筑服务校验牌表并向目录读取快照。M06 核对试算授权、同版正式解算器和隔离副本。M07–M10 核对启动器续局、回放及可信开发入口的调用与权限。将复核结果记入 T034 的验收记录。

## 云端自主验收

依据 [US7、FR-016–FR-018、SC-012–SC-014](spec.md)。在独立云端会话准备仓库锁定依赖、Node.js 24 LTS、Playwright Chromium 及其系统依赖。通过应用的正常构建预览运行正式前端，预先验证本地 3D 资源、WebGL 上下文和具备实际出帧能力的渲染后端。记录实际使用的浏览器和图形环境。

### 逐层业务入口

代理自主准备样本、发起操作、读取输出、执行断言并留存证据。四层各执行至少一条成功和一条失败路径。记录执行者及需要维护者代办的操作，SC-012 要求后者为零。每层依据[章程的职责](../../.specify/memory/constitution.md#层级分类)和[业务契约](contracts/business-interactions.md)验收。

| 层 | 正常入口与成功断言 | 失败及保持的约束 |
|---|---|---|
| 玩家端与观战端层 | 玩家操作经席位适配器发出 M02 并显示对应回执和本席视图。另验证 AI 玩家适配器把匹配 A02 的 A03 转成对应席位 M02，并读回结果。 | 过期模型任务不提交动作。观战或错误席位操作不得改变权威局面，界面只显示本授权范围可观察的信息。 |
| 对局层 | 通过 M01 建局后由 M02 触发待决策并应答，结合 M03、M04 核对待决策及单次确认的结算效果。 | 错误席位应答被拒，修订、命令回执记录和待决策进度无变化，也无新可见事件。 |
| AI 决策层 | 通过 A01、A02 选用并请求模型，从 A03 读回行动建议及请求 ID、席位、状态基准。 | 不可用模型返回可辨认原因，无行动生成通知，也无正式对局写入。 |
| 构筑与卡池层 | 通过 D02 保存合法卡组，通过 D01 读回名称、牌表及发行版。发布场景可用 D02 提交并核对 D03。 | 非法牌表保存被拒并指出字段，原记录可读且无部分保存。无效草稿发布无新版及 D03。 |

### 独立调试前端

使用测试宿主发放的正式席位授权接入统一玩家协议。映射测试指令的动作、目标和应答到 M02，从 M03 读取本席快照，从 M04 读取按连接顺序发布的可见事件。先提交会触发待决策的动作，从授权投影读出待决策 ID、候选及限制，再用新命令 ID 提交合法应答并依据回执、连续事件和最终视图判定确认结果。另从错误席位提交同一应答，核对拒绝、有效修订和权威状态均保持，合法应答仍可继续。调试端的指令输出经相同授权边界投影。

### 官方 2D 与 3D

1. 由真实鼠标或键盘输入从启动器打开各正式前端，选择固定牌表并开局，完成换牌、出牌或攻击、待决策应答，然后用合法动作结算至终局。隔离夹具固定对手行动和随机结果，代理从游戏界面执行己方操作。
2. 2D 核对手牌、目标选中或选择反馈、本席待决策、提交后的公开区域变化和终局文字。用对应回执、事件或回放核对目标、结算和胜负。
3. 3D 在相同业务操作之外，保留含有效战场、手牌和目标物体的实际出帧证据，以及输入前后的画面。固定机位下应保持旧版桌面与双方区域的构图，允许原有轻微呼吸位移。用实际指针分别选中预定手牌与战场目标，记录高亮或动作反馈，并用协议回执、事件或回放核对选中对象和实际结算对象一致。
4. 另从同一夹具分别运行调试前端、官方 2D、官方 3D。锁定规则和发行版、双方牌表、初始状态、对手动作及随机输入。以同一逻辑席位、进度、动作、目标和选项判定动作等价。对局临时标识按同一逻辑对象映射，比较同权限的快照、相关可见事件顺序和规则结果。任何差异都须关联到具体动作和观察点。

### 证据、首次通过与交接

证据保存场景 ID、源码提交或构建版本、规则和发行版、双方牌表、初始状态、随机输入或夹具引用、有序操作及断言结果。附对应的协议或对局记录，以及官方前端的界面轨迹、截图或录像。渲染不可用、缺输出或断言失败时，记录未通过的场景、失败步骤、预期与实测、环境、日志和现有界面证据。重跑并满足断言后才计入通过范围。证据按测试角色授权保存，公开投影证据不携带原随机源或私有数据。

每类首次代表性通过的条件如下。取得通过证据后，于继续后续实施前立即向维护者汇报。完整验收按 SC-012 和 SC-013 另行核对。

| 闭环 | 首条代表性真实路径 |
|---|---|
| 逐层测试 | 至少一层从正常业务入口执行有结算或写入反馈的一次成功路径并断言其结果，例如对局层合法应答并读回结算。 |
| 独立调试前端 | 经授权端口完成一次待决策应答，核对回执、事件和授权视图。 |
| 官方 2D | 从实际界面完成一次有合法目标或待决策应答的操作，读回界面结果并核对协议或对局记录。 |
| 官方 3D | 战场实际出帧，通过真实指针选中手牌及预定目标并完成一次合法结算，核对界面反馈及协议或对局记录。 |

首次汇报写明通过范围、剩余验收、复现入口及证据位置。随附可直接转交云空间编辑代理的提示词，逐项列出闭环环节、实际环境修改、版本或约束、用途、持久化配置位置或安装方式以及新会话复验命令和预期输出。某环节沿用现有环境时也要列出当前前置条件与复验步骤。提示词明确请求把实际环境改动保留为后续云会话的基础。汇报中提醒维护者批准把已验证流程制作成持久化 Skill。取得明确批准后才制作 Skill，发出汇报后可继续其他实施。
