# 离线验收指南

以下命令由实施任务定义。执行前准备 Node.js 24 LTS、iOS 与 Android 实机、桌面 Chromium，以及供所有设备访问的 HTTPS 构建预览。开发命令为 `npm ci`、`npm run dev`。验证命令为 `npm run test`、`npm run test:baseline`、`npm run test:e2e`。用 `npm run build` 生成站点与前端包，并将静态产物放到 HTTPS 预览。WebKit 模拟验证可用于早期检查，最终以已安装的实机实例为准。

## 安装、冷启动与权限

1. 在三类设备安装主体。iOS 从主屏幕图标打开，再在该实例内安装官方 2D、3D。等待启动器报告主体及前端就绪。准备兼容的第三方示例包和不兼容样本到本地文件。
2. 关闭所有窗口，手机开启飞行模式、电脑禁网，且关闭另一台设备。由安装图标重新打开游戏。官方 2D 通过触控或鼠标完成一局操作，官方 3D 验证选牌、目标、镜头、决策与 WebGL。
3. 在离线状态导入第三方示例包。关掉应用再次离线打开，从列表进入对局。导入不兼容包，检查旧包仍能打开。卸载示例包，检查官方前端仍可打开已有卡组和回放。
4. 使用测试客户端验证观战只见公开信息，第三方席位只见自己的允许视图且没有试算及宿主存储权限。卸载、重载或离开后旧连接无法再使用。核对官方客户端和第三方沿统一协议提交动作。分别升级客户端与核心，验证同版命令、查询、事件效果一致。

## 五个离线业务场景

| 场景 | 操作与预期 |
|---|---|
| PVE 初始化 | 用合法牌表分别从 2D 和 3D 发起，对照旧版真人先手、双方起手和首回合。提交非法牌表或不可用模型，收到失败原因，且无就绪事件。 |
| 「炽羽」 | 在固定状态用 2D 出牌，分别选择朱雀和非朱雀。只有选择席可看到候选。抽三张或两张，对手和观战只看到公开弃牌及张数。重复、过期、越权或错误候选均无新增结算。 |
| 构筑保存 | 保存合法牌表并重启，核对名称、牌表、发行版。模拟写入失败及跨版本缺卡错误。电脑导出后用手机本地文件离线导入，检查字段相同。 |
| EVE 初始化 | 配置不同模型并开始准备。确认双席和公开视图就绪，首个模型动作尚未执行。替换为不可用模型，检查失败席位及无就绪事件。 |
| 卡池发布 | 从发行版建立两个草稿。无效引用和中断各验证版本数及通知不变。有效发布后重启读回新版，进行中的对局仍按旧效果。多窗口模拟争抢，确认只出现一个写入所有者。 |

## 续局、规则解算和历史复现

1. 对「炽羽」依次验证三种中断：命令已确认但前端未收回执时断开；等待弃牌时完全退出；弃牌和抽牌已持久确认但回执送出前异常退出。重新接入或从冷启动恢复，核对原席位、待决策、原回执及抽牌仅发生一次。恢复后送达旧 AI 决定须被拒绝。
2. 在独立环境逐一载入该场样本的所有确认点。从等待弃牌的确认点重放原选择和随机输入，核对结算顺序、局面、回执与版本，确认原对局与原日志不变。
3. 在同版快照、同输入和随机样本下，对比正式核心与束搜索所用解算器。换用直接模型验证同一接口可生成行动。为两模型配置包含不可见手牌及牌堆顺序的样本，确认模型无法读到真实隐藏数据。单列旧 V6 偏差。
4. 核对「炽羽」两分支使用通用效果步骤。若实施批量效果重构，记录涉及卡牌、触发和结算差异，随后依目标版本校验整份卡池。

## 行为与回放对照

从 `quote/` 原始 HTML 记录来源、初始状态、玩家操作以及随机输入或结果。运行开局与换牌、出牌与攻击、回响、终焉、百川冰泉及「炽羽」样本，对比结算顺序、关键状态与胜负。旧版偏差随样本记载。新版选一条含随机结算的完整回放，在匹配版本下重放到同一终局，再用缺版本输入验证可辨认的诊断。实机结果记录设备、系统、浏览器、是否从安装图标启动、3D 输入与帧率观察、各场景结果及复现步骤。
