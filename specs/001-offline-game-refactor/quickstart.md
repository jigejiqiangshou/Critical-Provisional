# Phase 1 · 验收指南

## 当前可运行

从仓库根目录检查 Spec Kit 是否定位到正确规格与计划。

```sh
SPECIFY_FEATURE_DIRECTORY=specs/001-offline-game-refactor \
  bash .specify/scripts/bash/check-prerequisites.sh --json
```

预期指向 `specs/001-offline-game-refactor`，并列出研究、数据模型、契约和本指南。

准备原始 2D / 3D HTML，记录用于验收的文件校验和。用固定初始牌表、随机输入与动作序列制作旧版样本。验收时关闭外网访问，允许开发验证所需的本机通信。本地资源必须完整，包括插画和 3D 依赖。

## 实现后的验收场景

当前仓库处于设计阶段。游戏运行和测试命令由实施阶段提供。以下结果以[规格](spec.md)与[交互契约](contracts/business-interactions.md)为准。

| 验收项 | 操作 | 预期 |
|---|---|---|
| PVE / EVE 初始化 | 分别创建两种本地对局，再提交无效牌表或模型配置。 | 正确席位取得初始视图。未准备完成的会话返回原因。EVE 验收停在就绪状态。 |
| 暂停与恢复 | 在 2D 使用「炽羽」。分别弃朱雀牌和非朱雀牌，再尝试重复、过期或另一席位的应答。 | 抽牌差异与旧版一致，结算只发生一次，私有候选及新手牌按席位可见。 |
| 跨客户端接入 | 分别用 2D、3D、独立测试客户端和 AI 适配器读视图或提交合法动作。 | 同一命令由同一核心裁定。观战只见公开信息。 |
| 构筑保存 | 编辑并保存合法构筑，重新打开。再尝试保存非法构筑。 | 合法牌表及版本可重读。保存失败时原记录保留。 |
| 发布 | 对局进行时依次尝试发布缺少进化引用的草稿及合法草稿。 | 只有合法草稿新增一个版本。进行中对局维持原快照。 |
| 行为基线与回放 | 对比旧版开局、换牌、攻击、回响、终焉与冰泉。重放一局含随机结算的新版记录，再测试缺失版本。 | 相同输入下关键状态、事件顺序及胜负一致。新版回放重现终局，缺失版本有明确诊断。 |
