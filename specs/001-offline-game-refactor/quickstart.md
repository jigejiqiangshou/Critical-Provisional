# 离线与云端验收指南

以下命令由实施任务定义。执行前准备 Node.js 24 LTS、iOS 与 Android 实机、桌面 Chromium，以及供所有设备访问的 HTTPS 构建预览。开发命令为 `npm ci`、`npm run dev`。验证命令为 `npm run test`、`npm run test:baseline`、`npm run test:e2e`。用 `npm run build` 生成站点与前端包，并将静态产物放到 HTTPS 预览。WebKit 模拟验证可用于早期检查，最终以已安装的实机实例为准。

## 云端自主验收

1. 在云会话运行 `npm ci` 和 `npm run build`，由执行器启动隔离的预览和测试环境。运行 `npm run test:cloud -- preflight`，核对 Node、锁定的 Playwright 依赖、浏览器版本、启动配置、测试存储和 WebGL。记录实际渲染器和视口。以下 `test:cloud` 命令是计划的实施入口。
2. 运行 `npm run test:cloud -- layers`，按[四层业务入口](contracts/cloud-testing.md#四层业务入口)核对各层成功及失败结果。运行 `npm run test:cloud -- debug`，读取授权视图，用出牌、待决策应答和非法操作验证回执、有序事件、结算状态及失败不变量。
3. 分别运行 `npm run test:cloud -- 2d` 与 `npm run test:cloud -- 3d`。从启动器进入游戏，完成开局和换牌，出牌或攻击，回应待决策并推进到终局。从界面读回操作反馈和终局结果，同时留存对应的结算记录。3D 额外以截图和指针交互证据核对出帧、旧版固定机位、卡牌与目标拾取。
4. 运行 `npm run test:cloud -- parity`，从调试前端、2D、3D 分别执行同一固定场景。首选从合法牌表开局，用「炽羽」普通弃牌分支触发待决策并抽两张，随后经合法选牌和选目标推进至终局。以相同版本、初始条件、随机输入和固定对手配置核对同一可见范围内的关键状态、结算顺序和胜负。实现时用旧版样本校准牌序和动作脚本。
5. 每次运行保留场景输入、入口、操作顺序、观察、断言及证据引用。渲染不可用、输出缺失或断言失败时记录复现入口和阻塞证据，按相同场景复验直到实测通过。SC-012 至 SC-014 需核对完整报告，整个云端执行过程由代理自行完成。

## 首次通过汇报和新会话复验

逐层测试、调试前端、官方 2D、官方 3D 各有一次首报。首次通过可以是该类的一个代表路径。例如，逐层测试首条经正常入口提交并验证结算的对局用例，或官方 3D 首次经真实画布点击拾取卡牌与目标并核对结算。版本检查、环境预检与加载页面属于准备步骤。

1. 每类首次可用时，先以 `npm run test:cloud -- <入口> --representative` 执行该类的代表路径，入口为 `layers`、`debug`、`2d` 或 `3d`。代表路径实测通过并保存证据后，实施代理立即向维护者汇报，再继续该类完整验收和后续实施。每次汇报列明已通过和待验收范围、确切复现入口与证据。
2. 同次附一份可直接转交云空间编辑代理的提示词。提示词明确请求把已实测环境改动保留为后续云会话的持久化基础，逐项写明改动所支持的闭环环节、依赖或配置、实际版本或约束、用途、持久化位置或安装方式、新会话复验命令和预期。使用已有环境的环节同样写明所用能力与复验方式。
3. 同次提醒维护者批准将已验证的调试及复现流程制作成持久化 Skill。明确批准后才制作。发送汇报后可继续其余实施。当前会话取得的通过证据用于即时汇报，环境交接时另在新会话重跑所交接入口并保存结果。

## 安装、冷启动与权限

1. 在三类设备安装主体。iOS 从主屏幕图标打开，再在该实例内安装官方 2D、3D。等待启动器报告主体及前端就绪。准备兼容的第三方示例包和不兼容样本到本地文件。
2. 关闭所有窗口，手机开启飞行模式、电脑禁网，且关闭另一台设备。由安装图标重新打开游戏。官方 2D 通过触控或鼠标完成一局操作，官方 3D 验证选牌、目标、镜头、决策与 WebGL。
3. 在离线状态导入第三方示例包。关掉应用再次离线打开，从列表进入对局。导入不兼容包，检查旧包仍能打开。卸载示例包，检查官方前端仍可打开已有卡组和回放。
4. 使用测试客户端验证观战只见公开信息，第三方席位只见自己的允许视图且没有试算及宿主存储权限。卸载、重载或离开后旧连接无法再使用。核对官方客户端和第三方沿统一协议提交动作。分别升级客户端与核心，验证同版命令、查询、事件效果一致。

## 五个离线业务场景

| 场景 | 操作与预期 |
|---|---|
| PVE 初始化 | 用合法牌表分别从 2D 和 3D 发起，对照旧版真人先手、双方起手和首回合。提交非法牌表或不可用模型，收到失败原因，且无就绪事件。 |
| 出牌后暂停选择 | 示例用「炽羽」。在己方有朱雀和非朱雀单位、牌堆至少两张的固定局面，从 2D 出牌，分别选择弃一张朱雀牌和非朱雀牌。仅有权席位看到候选。两种选择均先弃牌再抽两张。弃朱雀牌时，己方场上的朱雀单位本回合攻击力 +1。核对对手和观战可见的弃牌、抽牌数及战场变化，并检查其视图中无私有牌身份。重复、过期、越权或错误候选均无新增结算。 |
| 构筑保存 | 保存合法牌表并重启，核对名称、牌表、发行版。模拟写入失败及跨版本缺卡错误。电脑导出后用手机本地文件离线导入，检查字段相同。 |
| EVE 初始化 | 配置不同模型并开始准备。确认双席和公开视图就绪，首个模型动作尚未执行。替换为不可用模型，检查失败席位及无就绪事件。 |
| 卡池发布 | 从发行版建立两个草稿。无效引用和中断各验证版本数及通知不变。有效发布后重启读回新版，进行中的对局仍按旧效果。多窗口模拟争抢，确认只出现一个写入所有者。 |

出牌样本的预期结果可核对 [2D 卡牌定义](../../quote/临界·模块化·2D版.html#L573)、[2D 结算处理](../../quote/临界·模块化·2D版.html#L1570)、[3D 卡牌定义](../../quote/临界·模块化·3D版.html#L961)和[3D 结算处理](../../quote/临界·模块化·3D版.html#L1958)。

## 续局、规则解算和历史复现

1. 对带选择的出牌样本验证三种中断。命令已确认但前端未收回执时断开。等待选择时完全退出。效果已持久确认但回执送出前异常退出。重新接入或从冷启动恢复，核对原席位、待决策及原回执，并确认结算效果只应用一次。恢复后送达旧 AI 决定须被拒绝。
2. 在独立环境逐一载入该场样本的所有确认点。从等待弃牌的确认点重放原选择和随机输入，核对结算顺序、局面、回执与版本，确认原对局与原日志不变。
3. 在同版快照、同输入和随机样本下，对比正式核心与束搜索所用解算器。换用直接模型验证同一接口可生成行动。为两模型配置包含不可见手牌及牌堆顺序的样本，确认模型无法读到真实隐藏数据。单列旧 V6 偏差。
4. 核对出牌样本的两条分支使用通用效果步骤，并按旧版行为断言结算顺序和结果。若实施批量效果重构，记录涉及卡牌、触发和结算差异，随后依目标版本校验整份卡池。

## 行为与回放对照

从 `quote/` 原始 HTML 记录来源、初始状态、玩家操作以及随机输入或结果。运行开局与换牌、出牌与攻击、回响、终焉、百川冰泉及「炽羽」样本，对比结算顺序、关键状态与胜负。旧版偏差随样本记载。新版选一条含随机结算的完整回放，在匹配版本下重放到同一终局，再用缺版本输入验证可辨认的诊断。实机结果记录设备、系统、浏览器、是否从安装图标启动、3D 输入与帧率观察、各场景结果及复现步骤。
