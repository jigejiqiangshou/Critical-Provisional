## 概要

以旧版 2D 和 3D 的可观察行为为基线，迁移到共用对局核心和玩家协议的离线 PWA。Story 7 将四层业务测试、协议调试、官方 2D 和官方 3D 的云端自主验收列入首版。实施代理在每类首条代表路径实测通过时立即交接证据和环境变更，随后完成全量云端与实机验收。

## 技术上下文

| 项目 | 路线 |
|---|---|
| 交付 | HTTPS 静态 PWA。主体安装后从一个启动器选择官方 2D、3D 或导入第三方包。主体及所选前端准备完毕后，每台设备可独立离线冷启动。 |
| 目标平台 | 首轮验证 iOS Safari 添加到主屏幕、Android Chrome 安装及桌面 Chromium 安装。2D 验证触控及鼠标，3D 在三类目标设备上验证 WebGL、输入和完整操作。记录实测系统、浏览器、机型及 3D 表现。 |
| 开发和构建 | TypeScript、Node.js 24 LTS、Vite。2D 采用 DOM，3D 延续 Three.js。构建产物包含本地图片、字体和渲染资源。 |
| 运行和接入 | 主程序负责启动器、文件选择、卡池维护及安装管理。对局与卡池的可信业务模块在宿主应用运行，计算和存储通过 Worker 隔离。前端包经隔离 iframe 和专用消息端口使用玩家协议。 |
| 数据 | SQLite WASM 在专用 Worker 通过 OPFS 持久化发行卡池，优先验证 `opfs-sahpool`。对局层以独立的 SQLite 数据库原子提交权威状态、日志与命令回执。用户卡组与安装记录各用独立的 IndexedDB 存储库。卡组通过文件跨设备迁移。 |
| 云端验证 | Vitest 验证四层业务入口。Playwright 在隔离 Chromium 中运行调试前端和官方 2D、3D。优先验证无头 Chromium 的 WebGL 出帧及输入能力。必要时实测软件 WebGL 或有界面运行，并记录实际采用的配置。 |
| 设备验收 | 在目标手机和电脑上独立验证安装、离线冷启动、文件选择、WebGL 与触控或鼠标操作。云端桌面结果和实机结果各自记录。 |

## 章程检查

| 原则 | 设计落实与复核依据 |
|---|---|
| I 离线与旧版基线 | 首次准备后以飞行模式冷启动。先采集旧 2D 与 3D 行为，按同输入比对逐步结果。裁决书驱动的改变另立需求。 |
| II 核心裁定 | 核心拥有随机源、待结算进度与决策。测试环境在开局准备时固定输入，判定、暂停与恢复由核心执行。用带选择步骤的旧版效果和回响验证该边界。 |
| III 共用协议 | 官方 2D、3D、第三方前端、独立调试前端与 AI 同用玩家协议，观战连接只读。调试前端只读回授权投影，模型只见本席信息。正式解算器复用规则版本和卡池快照，只在隔离副本中运行。 |
| IV SQLite 发布 | 卡组独立存储。发行使用 SQLite 事务，进行中对局持有开局快照。验证中断发布、并发写入与历史版本固定。 |
| V 可验证迁移 | 固定随机输入、命令、事件、关键状态和胜负。云端三端按同一场景比对授权范围内的结算。续局直接恢复最近确认快照，独立复现环境可重建任意已确认中间状态。旧记录按可复现程度出具说明。 |
| VI 四层职责 | 调试前端与官方前端共用玩家端与观战端层的协议桥。执行器、场景和证据位于测试目录。四层分别从已有业务入口验收，按稳定编号核对总图和层内图。 |

设计复核通过六条原则。单卡验收依照旧版代码准备样本、核对结果。浏览器出帧、移动端能力、第三方隔离和持久化列入早期实测，验收结果在实施阶段取得。

## 迁移顺序

1. 固定旧版样本并建立云端测试入口、隔离运行和证据目录。优先验证 Chromium 能运行旧版或渲染原型的真实画面和拾取。同时验证移动 PWA 冷启动、SQLite 写入后重启和第三方渲染隔离。若浏览器 VFS 不满足要求，先验证兼容 VFS。若设备独立离线与数据持久化仍无法同时满足，重新比较封装方案再确定发布形态。
2. 建本地会话、无界面核心、版本化卡牌目录和新 AI 模型，从正常业务入口尽早跑通逐层测试的首条真实路径。打通 PVE、调试前端的待决策指令往返和持久化续局。优先组合通用效果步骤，以带选择和条件分支的旧版效果验证结算与恢复。
3. 通过正常启动器、正式前端包及真实界面输入，分别跑通官方 2D 和 3D 的首条代表路径。与第三方离线安装、构筑管理、EVE 初始化、发布及回放实施衔接。步骤 2–3 中，每类首条路径实测通过后立即汇报，再继续后续实施。
4. 按 SC-012 至 SC-014 完成四层正负用例、官方 2D 和 3D 的完整 PVE、三端同场景对照及四份交接审查。另完成旧版对照、跨设备文件迁移和实机验收，记录支持环境与已知旧版偏差。

## 云端验收与交接

| 规格项 | 实施与验收 |
|---|---|
| FR-016 · SC-012 | 四层各从正常业务入口运行至少一条成功和一条失败用例。调试前端通过授权玩家协议完成一次待决策往返，并核对非法或越权操作的拒绝原因和业务状态。固定样本、动作、观察及断言由代理自行准备和执行。 |
| FR-017 · SC-013 | 官方 2D 和 3D 分别从启动到终局，覆盖换牌、出牌或攻击及待决策。以真实界面输入运行，从界面读回动作反馈与终局，再用回执、事件或回放核对。3D 另保留实际出帧、固定机位、卡牌和目标拾取的界面证据。用同一固定场景分别跑调试前端、2D 和 3D，并比较同一授权范围内的关键状态、结算顺序和结果。 |
| FR-018 · SC-014 | 逐层测试、调试前端、官方 2D、官方 3D 各自首次通过即汇报当前通过范围、待验收范围、复现入口和证据。每次附可直接转交云空间编辑代理的环境持久化提示词，并提醒维护者批准将已验证流程制作成持久化 Skill。收到明确批准后才制作 Skill，汇报发出后其余实施可继续。新会话复验在环境交接时执行，首报在当前会话发出。 |

渲染不可用、输出缺失或断言失败时，按场景记录阻塞、实际环境和证据，修复并实测后才计入通过范围。首次汇报和全量验收分别按 [验收指南](quickstart.md#首次通过汇报和新会话复验)执行。

