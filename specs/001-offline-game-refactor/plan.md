## 技术上下文

| 项目 | 路线 |
|---|---|
| 交付 | HTTPS 静态 PWA。主体安装后从一个启动器选择官方 2D、3D 或导入第三方包。主体及所选前端准备完毕后，每台设备可独立离线冷启动。 |
| 目标平台 | 首轮验证 iOS Safari 添加到主屏幕、Android Chrome 安装及桌面 Chromium 安装。2D 验证触控及鼠标，3D 在三类目标设备上验证 WebGL、输入和完整操作。记录实测系统、浏览器、机型及 3D 表现。 |
| 开发和构建 | TypeScript、Node.js 24 LTS、Vite。2D 采用 DOM，3D 延续 Three.js。构建产物包含本地图片、字体和渲染资源。 |
| 运行和接入 | 主程序负责启动器、文件选择、卡池维护及安装管理。对局与卡池的可信业务模块在宿主应用运行，计算和存储通过 Worker 隔离。前端包经隔离 iframe 和专用消息端口使用玩家协议。 |
| 数据 | SQLite WASM 在专用 Worker 通过 OPFS 持久化发行卡池，优先验证 `opfs-sahpool`。对局层以独立的 SQLite 数据库原子提交权威状态、日志与命令回执。用户卡组与安装记录各用独立的 IndexedDB 存储库。卡组通过文件跨设备迁移。 |
| 验证 | Vitest 验证无界面规则、契约和存储边界。Playwright 验证浏览器流程。离线冷启动、文件选择、WebGL 与触控另做移动实机验收。 |

详见 [路线取舍](research.md)、[数据模型](data-model.md)、[层级图](contracts/layer-boundaries.md)、[业务契约](contracts/business-interactions.md)、[对局场景时序图](contracts/scenario-sequences.md)、[前端包规范](contracts/frontend-packages.md) 和 [验收指南](quickstart.md)。

## 章程检查

| 原则 | 设计落实与复核依据 |
|---|---|
| I 离线与旧版基线 | 首次准备后以飞行模式冷启动。先采集旧 2D 与 3D 行为，按同输入比对逐步结果。裁决书驱动的改变另立需求。 |
| II 核心裁定 | 核心拥有随机源、待结算进度与决策，使用「炽羽」和回响验证暂停恢复。 |
| III 共用协议 | 官方 2D、3D、第三方前端、独立测试客户端与 AI 同用玩家协议，观战连接只读。所有模型只见本席信息。正式解算器复用规则版本和卡池快照，只在隔离副本中运行。 |
| IV SQLite 发布 | 卡组独立存储。发行使用 SQLite 事务，进行中对局持有开局快照。验证中断发布、并发写入与历史版本固定。 |
| V 可验证迁移 | 固定随机输入、命令、事件、关键状态和胜负。续局直接恢复最近确认快照。独立复现环境可重建任意已确认中间状态。旧记录按可复现程度出具说明。 |
| VI 四层职责 | 启动器和前端接入放在玩家端与观战端层。层级总图和四张模块图通过稳定编号核对两端交互。 |

复核结论为设计符合现有六条原则。移动端环境能力、第三方隔离和持久化列为早期原型和发布验收条件，实机结果待实现阶段取得。

## 迁移顺序

1. 固定旧版样本，同时验证移动 PWA 冷启动、SQLite 写入后重启和第三方渲染隔离。若浏览器 VFS 不满足要求，先验证兼容 VFS。若设备独立离线与数据持久化仍无法同时满足，重新比较封装方案再确定发布形态。
2. 建本地会话与无界面核心、版本化卡牌目录和最小测试客户端，打通真人对 AI 初始化、「炽羽」两个分支和持久化续局。优先组合通用效果步骤，同时建立受限解算器与新 AI 模型。
3. 实现启动器、官方 2D 与第三方示例包的离线安装闭环。完成构筑管理、EVE 初始化、发布、官方 3D 与回放的整体验收。
4. 对照旧版样本、跑完跨设备文件迁移及负例，记录支持环境与已知旧版偏差。

