## 技术上下文

| 项目 | 路线 |
|---|---|
| 交付 | HTTPS 静态 PWA。主体安装后从一个启动器选择官方 2D、3D 或导入第三方包。主体、首个官方卡池发行版及所选前端准备完毕后，每台设备可独立离线冷启动。 |
| 目标平台 | 首轮验证 iOS Safari 添加到主屏幕、Android Chrome 安装及桌面 Chromium 安装。2D 验证触控及鼠标，3D 在三类目标设备上验证 WebGL、输入和完整操作。记录实测系统、浏览器、机型及 3D 表现。 |
| 开发和构建 | TypeScript、Node.js 24 LTS、Vite。2D 采用 DOM，3D 延续 Three.js。构建产物包含本地图片、字体和渲染资源。 |
| 运行和接入 | 主程序负责启动器、文件选择、卡池维护及安装管理。对局与卡池的可信业务模块在宿主应用运行，计算和存储通过 Worker 隔离。前端包经隔离 iframe 和专用消息端口使用玩家协议。 |
| 数据 | SQLite WASM 在专用 Worker 通过 OPFS 持久化发行卡池，优先验证 `opfs-sahpool`。首次准备从本地交付资源装载首个官方发行版。发行版按锁定规则校验全量卡牌数据、稳定 ID 映射、跨卡引用及预设牌表，完成事务后才可使用。装载中断后可重试，保留已有的完整发行版本。对局层以独立的 SQLite 数据库原子提交权威状态、日志与命令回执。用户卡组与安装记录各用独立的 IndexedDB 存储库。卡组通过文件跨设备迁移，可按跨发行版稳定的卡牌 ID 与目标构筑规则跨版本导入。 |
| 验证 | 云端用 Vitest 验证四层业务入口和独立调试前端协议往返，用 Playwright Chromium 验证官方 2D、3D 的实际界面。准备锁定依赖、浏览器系统依赖和可出帧的 WebGL 环境，留存断言与界面、协议证据。iOS、Android 与桌面实机另按 SC-010 验证安装、断网冷启动、文件选择、触控或鼠标及设备表现，逐机留存记录。 |

## 章程检查

| 原则 | 设计落实与复核依据 |
|---|---|
| I 离线与旧版基线 | 以空存储执行正常首次准备，再以飞行模式冷启动，验证官方发行版、开局和草稿创建。先采集旧 2D 与 3D 行为，按同输入比对逐步结果。裁决书驱动的改变另立需求。 |
| II 核心裁定 | 核心拥有随机源、待结算进度与决策，使用待决策和回响场景验证暂停恢复。 |
| III 共用协议 | 官方 2D、3D、第三方前端、独立测试客户端与 AI 同用玩家协议，观战连接只读。所有模型只见本席信息。正式解算器复用规则版本和卡池快照，只在隔离副本中运行。 |
| IV SQLite 发布 | 卡组独立存储。发行使用 SQLite 事务，进行中对局持有开局快照。验证首次装载中断重试、中断发布、并发写入与历史版本固定。 |
| V 可验证迁移 | 固定随机输入、命令、事件、关键状态和胜负。首个可验收切片直接恢复最近确认快照，保留原待决策项与命令回执。后续由可信宿主的授权入口在独立环境重建任意已确认中间状态。旧记录按可复现程度出具说明。 |
| VI 四层职责 | 启动器和前端接入放在玩家端与观战端层。用层级总图、四张模块图和关键场景的实际调用复核两端交互、模块归属及状态所有权。T034 记录[架构边界复核](quickstart.md#架构边界复核)结果。 |

复核结论为设计符合现有六条原则。移动端环境能力、第三方隔离和持久化列为早期原型和发布验收条件，实机结果待实现阶段取得。

## 迁移顺序

1. 固定旧版样本，同时验证移动 PWA 冷启动、SQLite 写入后重启和第三方渲染隔离。若浏览器 VFS 不满足要求，先验证兼容 VFS。若设备独立离线与数据持久化仍无法同时满足，重新比较封装方案再确定发布形态。
2. 建立无界面核心和版本化卡牌目录。在公共基础中用同一事务确认权威状态、历史和命令回执（T032）。实现待决策和响应窗口的通用步骤（T015），按 LG-01–LG-08 迁移并对照开局换牌、出牌、攻击、进化、技能、回响、终焉和百川冰泉（T042）。按锁定规则校验并装载首个官方发行版（T041），留存旧版来源、稳定 ID 映射和预设牌表校验结果。用该发行版从本地会话的正常入口验证真人对 AI 初始化，并接入受限解算器与新 AI 模型。在完成离线安装闭环前，通过最小测试客户端打通带选择步骤的效果，验证直接续局保留原待决策项及命令回执（FR-010）。
3. 实现启动器、官方 2D 与第三方示例包的离线安装闭环。先从空存储验证首次装载、离线冷启动及开局。继续交付构筑管理、EVE 初始化、发布、官方 3D 和回放。按 FR-011、SC-007 实现可信宿主的授权选点及独立历史复现（T043）。整体验收时按 SC-010 补齐构筑查询和建草稿等[空存储验收步骤](quickstart.md#首次发行版与空存储验收)。
4. 对照旧版样本、跑完跨设备文件迁移及负例，记录支持环境与已知旧版偏差。
5. US7 随各业务入口交付持续验证。公共基础建立云端预检，各层入口和调试前端随 US1、US2、US3–US5 的业务实现验证。正式 2D 随交互接通运行，正式 3D 随渲染和拾取接通运行。每类取得首条通过证据即按 FR-018 交接。整体验收核对四层、三端同场景和两套正式界面终局证据。

| US7 闭环 | 验证入口及证据 | 任务与标准 |
|---|---|---|
| 四层业务入口 | Vitest 通过四层入口读取成功及失败结果，保存断言和不变量记录。 | T035、T036，SC-012、SC-014 |
| 独立调试前端 | 隔离测试会话内以授权玩家协议运行，保存命令、可见事件及快照。 | T037，SC-012–SC-014 |
| 官方 2D | Playwright 对正式构建执行实际界面输入，保存操作轨迹、界面反馈和对局证据。 | T038、T040，SC-013、SC-014 |
| 官方 3D | 同一浏览器流程取实际出帧、固定镜头及真实拾取证据，保存界面和协议结果。 | T039、T040，SC-013、SC-014 |

首次汇报及环境持久化提示词按[验收指南](quickstart.md#证据首次通过与交接)随对应任务执行。

## 项目结构

```text
src/
├── clients/       # 启动器、官方前端、前端包与玩家协议接入、AI 玩家适配器
├── match/         # 会话、权威核心、席位接口、回放
├── ai-decision/   # 决策接口、模型、隔离试算
└── deck-catalog/  # 构筑与用户数据、SQLite 卡牌目录、编辑与发布
tests/
├── baseline/      # 旧版基线和对照样本
├── contract/      # 层间协议、隔离、存储
└── acceptance/    # 自动化与实机离线验收
```
