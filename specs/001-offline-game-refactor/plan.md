## 摘要

在保留现有 2D / 3D 对局行为的前提下，将游戏拆为玩家端与观战端、对局、AI 决策、构筑与卡池四层。先固定旧版行为样本，再抽离权威结算和可暂停决策，用同一玩家协议接回两种视图及 AI。卡池以 SQLite 管理，构筑按版本只读查询，对局固定开局快照，编辑器校验后发布不可变新版本。对照裁决书的规则调整另行立项。

## 技术上下文

| 项目 | 规划基线 |
|---|---|
| 语言与运行时 | 草案采用 TypeScript 和 Node.js 24 LTS 作为开发验证基线。旧版 JavaScript 是迁移参考。 |
| 前端与依赖 | 延续 2D DOM 和 3D Three.js。开发预览与构建使用 Vite 作为候选；3D 依赖与插画在交付时本地提供。 |
| 数据存储 | SQLite 持久化已发行卡池。用户卡组使用独立的存储契约。开发验证优先试用 Node 的 SQLite 能力，最终驱动随交付形态确认。 |
| 验证 | 确定性行为样本、核心测试、协议与数据集成测试、Playwright 浏览器测试。 |
| 目标平台 | 本地浏览器验证形态优先。最终打包方式和目标操作系统范围留待确认。 |
| 性能基线 | 记录旧版初始化、AI 回合耗时与 3D 主线程表现，供同机对照。当前没有经审核的数值门槛。 |
| 范围 | 两个参赛席位、可选公开观战、PVE / EVE 初始化、出牌结算、构筑、卡池发布、版本化回放。 |

上述工具链是计划草案中的可验证默认方案。技术取舍和后续讨论范围见 [research.md](research.md)。

## Constitution Check

| 原则 | Phase 0 / 1 检查 |
|---|---|
| I. 离线运行与现有行为基线 | 按旧版代码建立样本，离线执行五类验收场景。裁决书变更另行验收。 |
| II. 由核心统一裁定对局 | 核心持有权威状态与结算进度。以「炽羽」和响应窗口验证暂停恢复与席位归属。 |
| III. 共用玩家协议与独立实现 | 2D、3D、独立测试客户端和 AI 使用统一协议。观战只读，旧 V6 试算与公开视图隔离。 |
| IV. 卡池只读快照与版本化发布 | 对局固定规则版本和卡池快照。构筑只读查询发行版。发布通过整份校验及事务验证。 |
| V. 可验证的迁移与可追溯的结算 | 对比旧版关键状态、事件顺序和胜负，记录回放所需版本、动作和随机结果。 |
| VI. 层级是最高架构抽象 | [层级与边界契约](contracts/layer-boundaries.md)定义四层及五张图。跨层边使用 Command、Query 或 Event，概念模型标明状态所在层。 |

Phase 1 复核结果为草案符合已确定的章程边界。下面三项待办仍需审核，影响范围内的接口冻结及实现以确认结果为准。

## 迁移顺序

1. 固定 2D / 3D 旧版输入、牌序、随机结果、关键状态与结算顺序，记录既有随机复现限制。
2. 抽离核心及本地会话，从单一命令入口跑通 PVE / EVE 初始化、席位投影及暂停恢复。
3. 迁移 SQLite 卡牌目录和只读快照、构筑保存及卡池发布，验证发行前后进行中对局的版本固定。
4. 接回 2D、3D 和 AI，迁移 V6 试算适配及回放，验证公开与私有视图和行为基线。

## 待明确事项

- [ ] **PEND-01 · 缺乏交互的稳定身份**
  为总图与两端边界图的同一项跨层交互定义稳定契约标识和版本规则。同时明确运行时命令、待决策项、事件、异步 AI 结果的标识范围、关联、去重与过期策略。完成标准是用对照表追踪每项交互，并用重复出牌及迟到 AI 回应案例验证。
- [ ] **PEND-02 · 状态所有权还需要进一步细化**
  将现有层级归属细化为逐状态矩阵，区分权威记录与投影，写明唯一写入者、读取者、存活期和失效条件。审核范围包括席位绑定、结算进度、可见视图、模型上下文、用户卡组与发布版本。完成标准是核心、对局接口、客户端及 AI 的读写分工可逐项核对。
- [ ] **PEND-03 · 缺乏业务不变量和禁止性约束**
  按关键场景整理可执行的约束、负责核验的模块及拒绝或回滚结果。优先覆盖行动权、隐藏信息、结算只执行一次、试算隔离、快照固定及发行原子性。区分现有约束、待确认约束与旧版已知偏差。完成标准是每条已接受约束都有可验证的反例。

## 复杂度审查

当前设计保持四层。隔离试算、版本化视图、回放记录均归入对应层。架构草案中无需申请章程例外。
