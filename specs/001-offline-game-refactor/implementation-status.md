## 目标平台

本次重构的设备适配和验收覆盖 Android Chrome 与桌面 Chromium 的已安装 PWA。iOS 适配已移出范围。两类目标设备仍须分别验证安装、断网冷启动、输入、文件选择和渲染。验证范围以 [SC-010](spec.md) 为准。

## 待验收与后续依赖

- **T003** 需要在 Android Chrome 已安装实例复验 OPFS 写入、独占接管、回滚及断网冷重启，记录机型、系统、Chrome 完整版本与最低验证版本。结果为 T006 提供存储路线依据。
- **T004** 需要在 Android Chrome 已安装实例复验离线准备、冷启动、文件选择、3D 出帧、宿主隔离及端口撤销。包体上限以实际文件字节计，待设备采样后确定。结果为 T005 和 T019 提供包入口设计依据。桌面验证观察到初始不透明 iframe 导航可能绕过 Service Worker。原型由入口响应的 CSP 建立不透明来源，并在核对受控入口、实例标记与来源后才发端口。源站的包入口回退应返回惰性 404。
- **阶段 2** 等待两项平台原型完成验收。SC-010 的首版离线开局、构筑和发布相关场景继续由对应正式任务提供证据。

## 云环境配置交接提示词

> 请为本项目后续云会话持久化 Node.js 24 LTS、可运行 WebGL 2 的系统 Chromium，以及会话可写的 npm 缓存配置。当前实测为 Node 24.22.3、npm 11.19.1、Debian Chromium 156.0.8078.79、ANGLE/Vulkan/SwiftShader。以仓库锁文件执行 `npm ci`，再运行 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run preflight:cloud`。预期读回绿色中心像素、黑色背景像素并报告 GL 错误为 0。并行的端到端测试可分别设置 `PLAYWRIGHT_PREVIEW_PORT`。
>
> 请提供一部 Android 实机或授权的实机服务，以及手机可访问的授权 HTTPS 预览。实机须能安装 Chrome PWA、调用系统文件选择器、完全退出应用、整机断网和从安装图标冷启动。T003 与 T004 使用各自独立的测试来源，T004 的 `/__t004__/entry` 静态回退应返回惰性 404。请通过原工作区取得原型分支，按其复验文档核对入口，并记录设备版本、配置位置、复验结果与环境仍缺的能力。此阶段只需要 Android 实机。
>
> 请把实际环境改动保留为后续云会话的基础，并返回全新会话的复验步骤。待首次代表性真实业务路径通过后按 FR-018 交接。将验证流程持久化为 Skill 前须经维护者明确批准。
