# 首版卡牌效果结构复核

[旧版对照样本](contracts/legacy-samples.md)中的 LG-05、LG-06、LG-08 触发位置、等待席位和后续执行顺序不同。旧版分别通过回合登记、攻击响应和冰泉专用队列管理流程。同一通用步骤需要表达下列三种可复用结构，才能由对局核心统一决定是否暂停，并在续局时回到同一规则位置。 [FR-012](spec.md#functional-requirements)

| 样本 | 需保留的规则结构 | 通用步骤 |
| --- | --- | --- |
| LG-05「余火」 | 发动时登记回合内重复生效的触发。每次己方单位死亡，先处理移出和亡语，再兑现已登记的本回合加成。回合结束清除登记。 | 由锁定版本的规则在权威状态中保存登记。死亡流程从触发入口依次调用亡语和有效登记的步骤。 |
| LG-06「镇岳」 | 原行动者的攻击进入响应窗口，另一席决定翻开或放弃。翻开先弃置镇岳并取消原伤害，放弃后继续原伤害。 | 攻击调用响应程序。选择步骤独立指定应答席位和放弃分支。继续调用方时保留原行动席位。 |
| LG-08「探珠」 | 先用核心随机输入生成候选，再作一项强制结果选择。零候选直接结束，唯一候选自动处理，多个候选暂停。先处理未选项，再处理已选牌能否入场。 | 采样为独立应用步骤。选择及恢复使用已确认的候选。数目不足时按结果规则继续，选中后的目标处理由版本化步骤跟在选择后。 |

若步骤及参数无法保存样本的触发时机或次数、应答席位、后续位置、依赖或顺序，且复现规则必须为特定卡名增加分支、交给前端裁定或绕开核心确认，即触发 FR-012 的批量重构要求。旧版 LG-06 和 LG-08 分别把恢复位置留在专用回响与冰泉流程，无法以一套候选和应答规则继续，符合此判据。

通用运行时把每个程序表示为具名步骤。应用步骤更新状态或消费核心随机输入，分支读取局面，调用步骤保存返回位置。选择步骤说明候选、数量、条件或结果语义、顺序、放弃权和可见范围。暂停时的候选、发起席位与返回位置都进入核心确认。恢复直接推进已确认的步骤，触发阶段的随机输入与状态更新只执行一次。

条件不足、结果为空、放弃或选中各自可转入后续步骤。唯一选择在当前确认中，公开决策事件以同一内容发送给玩家与观战；私有决策事件路由到有权席位。牌面规则、触发登记、到期和结算时机由 T042 接入正式规则，T045 对首版卡池逐条迁移并核对受影响结构。

## 首版迁移中新发现的差异（进行中）

「朱厌」牌面规定攻击时先对目标造成 1 点穿透伤害；规则书 §5.4.1 规定穿透跳过护盾。旧 2D 和 3D 页的普通单位目标攻击路径调用先击，但核心攻击路径遗漏该处理。迁移应在核心目标也先执行穿透，再执行普通攻击；先击已造成终局时不再执行后续普通伤害。独立测试须覆盖核心护盾、先击致终局及响应取消，保留此差异以供旧版对照。此项并不表示 T045 已完成。

「朱雀羽」在旧版通过死亡队列延后交互：同一动作链中的群伤先逐个结算，动作链结束后按死亡次序决定是否弃牌并抽牌。将其与普通即时遗蜕一起压入队列会使首个死亡在后续目标受伤之前暂停，改变可见过程；因此交互型死亡代价单独进入可持久化的延迟队列，主队列清空后再依次处理。独立样本须包含多个目标、可放弃与暂停恢复，并继续核对相同触发结构的其他卡牌。
