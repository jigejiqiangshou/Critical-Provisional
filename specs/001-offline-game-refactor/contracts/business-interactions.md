# 业务交互契约

## 稳定标识与传输

下表的 ID 对应[总图及两端模块图](layer-boundaries.md)。同一 ID 的方向、语义与业务含义在三处一致。稳定键为交互 ID 与契约主版本。新增可忽略字段递增次版本。删除字段或改变其含义、权限和命令效果升级主版本。连接在握手时确认主版本相同，选择双方支持的最高共同次版本。主版本不符和无共同次版本须分别返回可辨认的拒绝原因及双方声明的协议版本范围，随后关闭失败连接。协商完成前不得授权席位、接收业务请求或推送业务事件。命令和查询使用类型化请求及返回结果，事件通过相应连接通知。浏览器边界用结构化消息，可信模块可直接调用同一契约。初始契约为 1.0。

| ID · 类型 | 发起方 → 接收方 | 请求、返回或通知 |
|---|---|---|
| M01 · Command | 玩家端与观战端 → 对局 | 创建 PVE/EVE，携带请求 ID、席位配置、模型及规则和发行选择。返回已就绪会话引用或失败席位和原因。 |
| M02 · Command | 玩家端与观战端 → 对局 | 出牌、攻击、回合动作或决策回应。携带命令 ID 与期望修订号，决策回应携带决策 ID。返回受理回执或目标、行动权、过期等可辨认原因。 |
| M03 · Query | 玩家端与观战端 → 对局 | 取当前席位或公开视图，返回快照与本连接的序号。Query 期间业务状态保持不变。 |
| M04 · Event | 对局 → 玩家端与观战端 | 当前连接可见的就绪、待决策、公开动作和结果。事件携带会话 ID、连接流序号与修订号，可见时关联起因命令。 |
| M05 · Query | 对局 → 构筑与卡池 | 按目标规则和发行版取得快照与牌表校验结果。 |
| M06 · Query | AI 决策 → 对局 | 按获准的模型任务查询本席试算种子及锁定版本的正式规则解算器能力。解算只读使用规则定义，在假设补足的副本上计算。 |
| A01 · Query | 玩家端与观战端 → AI 决策 | 查询指定模型的可用性和版本。 |
| A02 · Command | 玩家端与观战端 → AI 决策 | 准备模型席位或请求生成行动，返回准备结果或生成受理。生成请求附请求 ID 与当前可见决策上下文。 |
| A03 · Event | AI 决策 → 玩家端与观战端 | 向原 AI 适配器通知行动已生成，回带请求 ID 和状态基准。适配器另发 M02。 |
| D01 · Query | 玩家端与观战端 → 构筑与卡池 | 查询卡池或卡组、预检导入牌表、预检草稿或导出卡组内容。返回数据或可定位诊断。 |
| D02 · Command | 玩家端与观战端 → 构筑与卡池 | 保存或导入卡组、创建或更新草稿、发布发行版。返回正式记录或校验、存储和版本错误。 |
| D03 · Event | 构筑与卡池 → 玩家端与观战端 | 发行事务提交后通知宿主维护界面新增版本。 |
| D04 · Query | 构筑与卡池 → 对局 | 查询选定规则版本支持的触发器及效果。 |

D01 预检和 D02 正式导入均按所选目标发行版校验文件完整性、卡牌 ID 是否存在以及整副牌表是否合法。构筑服务用跨发行版稳定的卡牌 ID 查目标版本，无需加载源版本或比较两个版本的卡面和效果。缺卡时返回缺失 ID 和目标发行版。D02 在写入时重新校验，成功后原子保存名称、牌表与目标发行版，失败保留原文件及既有记录。

启动器经 A01、A02 预备所选 AI 适配器，再以 M01 提交准备结果。对局会话核验并绑定对应席位，失败时宿主释放预备资源，接口无就绪事件。

M02 先校验连接仍有效、与目标会话匹配且具备提交该席位命令的权限。仅通过这道检查才以当前会话、授权席位和命令 ID 查找回执。之后按下表处理。

| 提交情形 | 原请求反馈 | 业务状态及事件 |
|---|---|---|
| 同席位同 ID 同内容 | 返回原回执，即使原修订号或决策已失效。 | 无新增结算、修订或可见事件。 |
| 同席位同 ID 改内容 | 返回命令 ID 冲突。 | 无新增结算、修订或可见事件。 |
| 新 ID 重交已完成决策 | 返回决策已失效。 | 无新增结算、修订或可见事件。 |
| 未授权、其他席位冒用或授权已撤销 | 授权检查拒绝，活动连接得到未授权反馈。已关闭连接由宿主报告连接或授权失效。两种情况下均不查询或交付原回执，也不确认其存在。 | 无新增结算、修订或可见事件。 |

其余新命令按修订号、行动权和决策有效期检查。合法决策只能消费一次。对局层先在候选状态应用命令，再通过同一 SQLite 事务提交权威快照、历史记录和命令回执。事务成功后才发布可见事件并返回正式回执。事务失败时保留上次确认进度。重启直接载入最近快照并核对原席位绑定，重新授权连接。旧模型任务失效；适配器可从恢复视图发起新任务。状态变化、选择取消或席位失效后，迟到 AI 结果由适配器丢弃，核心再次验证提交的修订号与决策 ID。客户端看到序号缺口时通过 M03 重取当前快照，并从快照序号接收后续更新。观战与各席位各用自己的有序流，流序号不暴露私有事件数量。

## 业务不变量与反例

| 不变量 | 裁定方及失败后的状态 | 验收反例 |
|---|---|---|
| 当前有权席位持有仍有效的决策 | 对局接口与核心拒绝，权威状态及待决策进度保持。 | 观战提交动作，另一席应答待决策，或有权席提交失效选择。 |
| 只有授权视图可离开宿主 | 对局接口先投影，授权由可信宿主发放。失效连接关闭，观战只收公开状态。 | 第三方连接要求对手私有视图、内部试算或已经撤销的席位，核对返回和事件不含受保护数据。 |
| 每个命令至多执行一次，每个决策只消费一次 | 对局接口返回缓存回执或冲突，核心拒绝失效决策。无额外结算、事件或修订。 | 同一应答命令重试，给同 ID 换参数，或用新 ID 重交已完成选择。 |
| 试算限于席位可见信息及假设样本 | 对局接口只发本席观察和同版规则能力，解算器在隔离副本使用独立随机流。 | 改变对手真实隐藏区，核对相同席位观察与相同假设种子产生相同试算结果，且真实局面未改变。 |
| 确认状态、命令回执及历史一致 | 对局层在同一事务确认。重启直接续局。独立环境可读取历史确认点并复算，原会话存储保持原样。 | 应答确认后、回执送出前退出，重启后重试取得原结果且无重复结算。从历史等待点复算并核对原记录。 |
| 对局持有开局快照 | 会话和核心保留原版本，发布事务只新增版本。 | 活跃对局中发布效果变更，当前局沿用旧效果，新局可选择新版。 |
| 发行版原子提交，卡组原子保存 | 构筑存储和 SQLite 发布模块分开提交。失败时原记录仍在，版本列表保持，且无成功通知。 | 发布缺失跨卡引用或模拟写入中断，检查版本数和发布事件。模拟卡组写失败后读回原卡组。 |
| 旧回放偏差有可核验归因 | 回放模块以版本和随机输入验证新版。旧版已知随机限制在样本记录中关联参考文件、条件和观察结果。 | 以含随机结算样本重放到同一终局，再移除匹配版本检查明确错误。 |
