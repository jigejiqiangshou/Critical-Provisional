# 云端自主验收契约

适用于 Story 7、FR-016 至 FR-018 和 SC-012 至 SC-014。测试执行器以独立浏览器配置、源和临时存储运行。可信测试启动器准备固定场景并锁定规则版本、卡池发行版、牌表、初始条件、随机输入和对手模型。官方前端仍经正常启动器开局、渲染和提交动作。对手模型使用正式的独立模型接口及对应席位观察。场景准备和证据收集入口随测试构建提供。工件定义见[隔离测试数据](../data-model.md#隔离测试数据)。

## 四层业务入口

每层单独执行至少一条成功用例和一条失败用例。失败须同时核对可辨认的原因及该层负责的业务不变量。编号沿用[业务交互契约](business-interactions.md)。

| 层 | 正常入口与成功断言 | 失败断言 |
|---|---|---|
| 玩家端与观战端 | 通过前端正常交互处理程序提交玩家操作并读回可见反馈。另让真实 AI 玩家适配器接收 A03，再发送 M02，核对其关联的席位、回执和可见反馈。 | 给适配器送达已过期的 A03，核对失效原因、无新席位命令及原视图未受该结果影响。 |
| 对局 | M01 创建会话、M02 出牌并应答待决策，通过回执、M03 和 M04 核对结算。 | 对失效决策或错误席位发送 M02。拒绝原因与行动权或决策状态相符，核心修订、局面及待决策不变，且无新增结算事件。 |
| AI 决策 | 经 A01、A02 准备并请求实际模型，从 A03 读回绑定原请求、席位和状态基准的合法行动建议。若使用试算，固定假设输入并核对正式对局未变化。 | 请求不可用模型，核对拒绝原因，且该请求无 A03 和可提交行动。 |
| 构筑与卡池 | 经 D02 保存已校验卡组，用 D01 重开并核对名称、牌表和发行版。 | 对有效变更模拟存储写入失败，核对存储错误、原记录照常读回且没有部分更新。可另通过无效草稿覆盖发布不变量。 |

## 调试前端的玩家协议

独立调试前端作为测试用自定义前端，通过现有加载、握手和席位绑定接入。测试执行器可要求它提交动作或决策、查询当前视图、收集可见事件。动作对应 M02，带命令 ID、所观察的修订号以及应答所用的决策 ID。查询对应 M03，事件订阅对应 M04，按连接内序号消费并在出现缺口时重新查询。前端记录授权视图、命令回执、有序事件及待决策项，执行器据此选择下一步并断言。席位从端口授权确定。

使用合法出牌、读取待决策、回应并读回结算作为代表路径。完整验收再提交一次非法或越权指令，对比前后可见局面及修订，并核对拒绝原因和无额外结算事件。完整夹具和仅供测试的权威核对记录由可信执行器持有。

## 官方前端与三端对照

官方 2D 使用正常点击或键盘交互。官方 3D 基于固定桌面视口下实际可见的卡牌和目标，以指针输入触发正常画布拾取。3D 记录有效画面、选卡与目标反馈及结算后的画面，核对旧版固定机位下的相对布局和取景。正常的细微镜头动画保留。官方两端均直接从界面断言至少一次操作反馈和终局显示，并以同次运行的回执、可见事件或回放核对权威结算。

同一固定场景分别从调试前端、官方 2D 和官方 3D 执行等价业务动作。对照按席位授权范围、动作和确认点对齐，核对结算顺序、关键状态和结果。连接、命令等运行时标识用于各次运行内的关联。比较时使用其业务含义及相对顺序。报告引用场景和版本、按顺序的操作及观察、预期和实际断言，以及足以定位失败的截图、浏览器跟踪或对局记录。

渲染不可用、结果缺失或断言失败时保存实际环境、失败步骤和诊断。修复后从同一入口复验，通过记录须有完整证据。首次汇报流程见 [验收指南](../quickstart.md#首次通过汇报和新会话复验)。
