# 前端包与启动器契约

## 前端包 v1

首版用 `.critical-ui` 单文件。文件为 UTF-8 JSON，包含 `formatVersion: 1`、`id`、`version`、`name`、`protocolMajor`、`protocolMinMinor` 和 `entryHtml`。ID 为稳定的 ASCII 小写带点命名，版本使用语义版本。入口是自包含 HTML，脚本、CSS、图片和 Three.js 等资源由构建器内联或以 data URL 嵌入。首次原型测定包体上限并写入前端开发文档，解析前检查大小，避免超配额和内存峰值。官方 ID 由宿主预留，官方发行完整性通过宿主随版本发布的清单校验。

安装器检查格式、版本、入口资源、ID 冲突与可用空间。启动器须区分缺少资源、包损坏、格式或协议不兼容、包 ID 冲突及存储空间不足。ID 冲突须指出冲突 ID。第三方包使用官方预留 ID，或从新装入口导入与已安装包同 ID 的文件时，均须拒绝。空间预检失败和提交时的配额失败均须提示空间不足，可释放空间后重试。超过包体上限须提示上限。验证通过且用户确认名称与来源后，宿主将初装包暂存为独立候选实例，经受控入口执行与升级相同的启动检查。启动检查通过后，宿主以同一事务提交入口和活动安装记录。只有该事务成功才在已安装列表展示，并进入正常授权流程。

玩家可从已安装的第三方前端条目进入离线升级，选择 ID 与该条目相同且版本更高的本地文件。文件通过包格式、资源和协议兼容性检查后，由玩家确认文件来源。来源确认以玩家判断为准。取消确认时保留原活动版，并结束本次升级。升级候选版作为独立实例启动。宿主确认候选版已加载通过验证的受控入口、该实例完成一次性握手，并在其专用端口上按玩家协议协商出双方支持的版本，才允许提交入口和活动版本切换。启动检查只交换握手与版本协商所需的信息。提交成功后结束升级候选实例并关闭其检查端口。新版成为下次打开该前端时使用的活动版本。

已运行的旧实例继续使用原版本、所需资源及仍有效的端口和授权，直到按正常生命周期结束。下次打开该前端时，宿主从活动安装记录启动新版，由新版实例按正常流程取得席位或观战授权。玩家可选择续接同一局，其状态和待决策项来自对局核心。

入口加载失败、握手校验失败、协议协商被拒绝，或候选版未在宿主启动超时前完成上述检查时，启动器提示对应的失败环节。宿主结束候选实例并撤销其端口及启动期间的临时资源。上一活动版本、已运行实例及其有效端口和授权保持可用。上一版本尚未运行时可从列表打开并重新授权。初次安装失败时，清除暂存候选，包 ID 可再次从新装入口导入。活动记录提交失败按相同流程清理候选，保留此前有效的安装和授权。 [玩家协议协商](business-interactions.md#稳定标识与传输)

卸载结束该包的运行实例并撤销其全部端口和授权，再删除包数据及安装记录。上述失败和卸载均保留卡组、对局与回放数据，其他有权前端仍可使用这些数据。

## 离线启动和隔离

1. 玩家从已安装 PWA 启动，通过文件选择器导入第三方包，或在官方列表单独准备 2D、3D。启动器显示每个包是否可离线打开。
2. Service Worker 从已验证安装记录提供专用入口响应，入口带限制性 CSP，包括文档自身的沙盒设置。候选实例只能加载已验证的暂存受控入口，正常实例固定使用启动时由活动安装记录选定的受控入口。升级后，对旧实例仍需的入口与资源保留至该实例结束。入口只接受内联需要的脚本和样式、允许的内嵌静态资源，限制外部资源请求和嵌入。宿主控制 iframe 允许的入口和响应范围。在目标浏览器验证 frame 自导航时连接撤销，以及游戏主体的 DOM 与持久化存储隔离。
3. iframe 启用沙盒脚本能力，保持不透明来源。宿主用实际 frame 实例和一次性握手标记确认启动，仅在初始化传入 MessagePort。握手和协商只交换启动所需信息。宿主在协议协商成功后才为端口授予席位或观战权限，并按协议 schema 验证端口消息。卸载、离开、重载终止或失去授权时关闭端口，重新打开须由宿主再次授权。
4. 第三方前端可以访问玩家选定席位允许的数据。对手隐藏信息、模型试算种子及解算器能力、宿主文件操作、发布和用户数据访问留在可信宿主。启动器在前端外提供开局配置、返回、构筑、发布与文件迁移入口。包元数据和显示名称用普通文本呈现。

第三方自行分发文件即可，首版的安装入口位于启动器。兼容的示例包、构建及协议验证命令随项目提供。
