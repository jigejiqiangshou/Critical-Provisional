# 前端包与启动器契约

## 前端包 v1

首版用 `.critical-ui` 单文件。文件为 UTF-8 JSON，包含 `formatVersion: 1`、`id`、`version`、`name`、`protocolMajor`、`protocolMinMinor` 和 `entryHtml`。ID 为稳定的 ASCII 小写带点命名，版本使用语义版本。入口是自包含 HTML，脚本、CSS、图片和 Three.js 等资源由构建器内联或以 data URL 嵌入。首次原型测定包体上限并写入前端开发文档，解析前检查大小，避免超配额和内存峰值。官方 ID 由宿主预留，官方发行完整性通过宿主随版本发布的清单校验。

安装器检查格式、版本、入口资源、ID 冲突与可用空间。用户确认显示名称与来源后，宿主把入口和安装记录放在同一事务内提交。导入失败保留已安装版本。升级先完整提交候选版，经宿主启动确认后切换活动版本，启动失败可以回到上一可用版本。卸载结束运行实例，再删除对应包数据。游戏数据由原存储所有者继续管理。

## 离线启动和隔离

1. 玩家从已安装 PWA 启动，通过文件选择器导入第三方包，或在官方列表单独准备 2D、3D。启动器显示每个包是否可离线打开。
2. Service Worker 从已验证安装记录提供专用入口响应，入口带限制性 CSP，包括文档自身的沙盒设置。仅已验证安装的受控入口可供加载。入口只接受内联需要的脚本和样式、允许的内嵌静态资源，限制外部资源请求和嵌入。宿主控制 iframe 允许的入口和响应范围。在目标浏览器验证 frame 自导航时连接撤销，以及游戏主体的 DOM 与持久化存储隔离。
3. iframe 启用沙盒脚本能力，保持不透明来源。宿主用实际 frame 实例和一次性握手标记确认启动，仅在初始化传入 MessagePort，握手不含游戏或座位敏感数据。后续按协议 schema 验证端口消息，宿主为端口固定席位权限。卸载、离开、重载终止或失去授权时关闭端口，重新打开须由宿主再次授权。
4. 第三方前端可以访问玩家选定席位允许的数据。对手隐藏信息、V6 种子、宿主文件操作、发布和用户数据访问留在可信宿主。启动器在前端外提供开局配置、返回、构筑、发布与文件迁移入口。包元数据和显示名称用普通文本呈现。

第三方自行分发文件即可，首版的安装入口位于启动器。兼容的示例包、构建及协议验证命令随项目提供。
